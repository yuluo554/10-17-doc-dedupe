## 三、退出码契约（全项目一致）

| 码 | 语义 | 典型场景 |
|---|---|---|
| 0 | 正常完成，且未检出需要处置的簇 | `scan` 完成、`report` 无近重复 |
| 1 | 正常完成，**检出了结果**或门槛未达标 | `report` 存在近重复簇；基准未达标 |
| 2 | 用法错误或输入不可用 | 路径不存在、参数互斥、未知子命令、缺 `--confirm` |
| 3 | 依赖缺失或阶段未就绪 | 缺 `web` extra、数据库 schema 版本不支持 |

**纪律**：退出码契约锁进测试；README 明示语义（`report` 返回 1 是"检出结果"，不是故障）。
"失败件"（坏 PDF/不可读文件）不得改变退出码语义——它们是 `skipped` 状态，计入汇总，
除非全部文件都不可用（此时 exit 2）。

## 四、隐私与合规对标

| 承诺 | 落点 | 取证 |
|---|---|---|
| 纯本地、零上传、零遥测 | 无任何 HTTP 客户端调用；Web 只绑定 `127.0.0.1` | 源码 import 审计；socket 拦截测试；`serve` 监听地址断言 |
| 页面零外链 | 单文件内联 CSS/JS | 渲染出口常驻断言 + 测试 |
| 真实文档不入仓 | `.gitignore` 白名单只放行 `data/samples/**` | `git ls-files` 复核 |
| 索引与隔离区不入仓 | `.gitignore` 锚定 `*.db`、`.dedupe-quarantine/` | `git status` 干净 |
| 只隔离不删除 | 代码层无 `os.remove`/`unlink` | AST 静态断言 |
| 不构成抄袭判断 | 报告与页面固定免责段 | 文案断言 |

## 五、发布三件套对标（M6）

| 件 | 落点 | 核验 |
|---|---|---|
| git tag | annotated tag `v0.1.0` | `git tag -l`、`git cat-file -p <tag>` |
| Release 附产物 | 源码 zip（含 sha256 台账） | `gh release view --json assets`、本地副本 sha256 复算 |
| 发布留档 | `plan/RELEASE-M6.md` | tag 树内存在；tag 时点/后追加分栏 |

**口径**：选 A 口径（**Release 附产物**，≥1 个手工上传附件，本地留副本 + sha256）。
源码 zipball 不单独视为"附产物"。

## 六、边界与非目标的对标检查

| 边界 | 检查方式 |
|---|---|
| 首期不做 OCR | 依赖里无 OCR 库；扫描件 PDF 只落 `skipped:no_text_layer` |
| 不做语义向量检索 | 依赖里无 embedding/向量库；README 明示 |
| 不自动删除 | AST 断言 + 端到端"无 confirm 不动作"用例 |
| 不处理加密 PDF | 只标 `skipped:encrypted` |
| 不做云同步 | 无账号、无上传、无遥测 |
| 模板族永不自动处置 | `cluster.py` 对 `template` 不产出 keep 建议；测试断言 |
| 首期仅 5 模块 | `plan/03` §六 扩展项表；代码里无 PPTX/XLSX 抽取 |
