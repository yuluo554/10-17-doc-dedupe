# 04 · 数据计划

- 版本：v1（2026-10-17，M0 计划期）
- 上游：`data/README.md`（依据查证 + 数据源可获取性 + 数值口径的唯一出处）
- 本文档只描述**怎么造数据、怎么带真值、怎么复核**；所有阈值/位宽/召回口径一律引用
  `data/README.md` §四，本文不复写数值

## 一、数据来源结论

本题**无外部数据依赖**：

| 类别 | 来源 | 入仓 | 说明 |
|---|---|---|---|
| 合成文档（PDF/DOCX/MD/TXT/HTML） | `tools/gen_samples.py` 程序化生成 | ✅ `data/samples/` | 全部假名，白名单见 `data/README.md` 附录 |
| 植入真值 | 生成器同步产出 `data/samples/truth/manifest.json` | ✅ | 只记"事实分组与差异类型"，不记分数 |
| 真实用户文档 | **不采集** | ❌ | 隐私红线；仓库内永不出现 |
| 外部数据集 | 不使用 | — | 无许可与隐私风险 |

**结论**：数据可 100% 自制、可版本化、可离线复现，基准无需网络。

## 二、合成样本设计

### 2.1 规模

首期样本集规模按里程碑分两档：

| 档 | 用途 | 规模口径 |
|---|---|---|
| 冒烟档 | 每次提交跑 | 小规模，保证 < 数秒完成 |
| 全量档 | 里程碑收尾 / 发布前 | 1000 份量级（含噪声文档），覆盖模块① 的规模验收 |

具体份数不写进本文（会随实现漂移），一律由生成器的 `--check` 输出与 `data/samples/truth/manifest.json`
的 `counts` 字段回填。

### 2.2 必须覆盖的形态

| 形态 | 说明 | 服务的验收 |
|---|---|---|
| 改写版 | 同正文替换若干词/句 | 模块② 召回（近重复） |
| 截断版 | 删掉首/中/尾若干段 | 模块② 召回 + 模块④ "仅差 X 段" |
| 换格式版 | 同一正文分别落 DOCX/PDF/MD/TXT/HTML | 模块② 跨格式指纹一致 |
| 完全重复 | 同名内容不同文件名 | 模块③ `exact` 档 |
| 模板族 | 同模板不同字段（合同/发票/周报） | 模块③ `template` 档单列 |
| 无文本层 PDF | 只有图片/空文本层 | 模块① `skipped:no_text_layer` |
| 加密 PDF | 有密码 | 模块① `skipped:encrypted` |
| 全半角混排 | ＡＢＣ１２３ 与 ABC123 | 模块② 归一化 |
| 页眉页脚与页码 | 跨页重复短行 + 页码 | 模块② 归一化 |
| 无关文档（负样本） | 同领域但内容无关 | 误报率 0 |
| 不支持格式（补充） | 旧版 `.doc` / `.rtf` / 伪装成 `.pdf` 的文本 | 模块① `skipped:unsupported` |

**关于"不支持格式"一行**：`plan/04` v1 的三态只列了 `no_text_layer` / `encrypted` 两种失败。
M1 落地时 `extract.py` 明确需要第三种 `skipped:unsupported`（未知格式不得被当成空文档），
样本集因此补了三份对应样例。真值 manifest 把它们放在独立的 `unsupported` 段，
**不进入 `by_variant` 的枚举统计**——`variant` 枚举描述的是抽取结果，不是"我们不读的格式"。

**真值规模（M1 实测）**：101 个文档、37 个真值组（near 20 / exact 4 / template 3 / negative 10），
另有 4 个跳过样本与 3 个不支持格式样本。具体数字以 `truth/manifest.json` 的 `counts` 为准。

### 2.3 真值语义（一次性定清）

`truth/manifest.json` 的每条记录：

```json
{
  "sample_id": "S0001",
  "group_id": "G007",
  "tier": "near",
  "variant": "rewrite",
  "files": ["S0001_a.docx", "S0001_b.md"],
  "base": "S0001_a.docx",
  "diff_kind": "rewrite"
}
```

**硬纪律**：

1. 真值**只记输入与期望分组**，**不记相似度分数、不记任何 `observed_*` 字段**——
   分数由引擎运行时实算。真值里出现观测值即视为缺陷。
2. `tier` 只能取 `exact` / `near` / `template` / `negative` 四值；`negative` 表示"不应与任何
   其他组同簇"。
3. `variant` 只取 `original` / `rewrite` / `truncate` / `reformat` / `template` / `no_text_layer`
   / `encrypted` / `noise`。
4. 真值分组**可由输入独立复算**：组内成员关系由生成器的声明决定，不由引擎输出反推。

## 三、生成器纪律

`tools/gen_samples.py`：

- **固定 seed**：默认 seed 写死在生成器常量里，`--seed` 可覆盖；同 seed 产物**逐字节一致**。
- **确定性 RNG**：自实现 splitmix64（不用 stdlib `random`，其序列不承诺跨版本一致）。
- **不读系统时钟**：所有时间字段由固定基准时间偏移生成；产物无当前时间戳。
- **DOCX/PDF 时间戳收口**：`python-docx` 的 `save()` 会把当前时间写进 zip 条目 → 落盘后统一
  用固定时间戳 `(1980,1,1,0,0,0)` + `create_system=0` 重写 zip（`tools/docxutil.py`），
  保证跨平台位级一致。
- **PDF 自带写手**：`pypdf` 写出的文件 `/ID` 取时钟、加密用 `os.urandom`，同一输入两次产物不同，
  `--check` 永远不可能绿。因此 `tools/pdfutil.py` 自带一个最小 PDF 写手：文件 id 由固定标签哈希、
  加密密钥由固定口令派生、不写任何时间戳；文本用 CID 字体 + ToUnicode 映射，pypdf 可正常抽取中文。
  加密样本使用**非空用户口令**——空口令会被透明解密，根本走不到 `skipped:encrypted`。
- **`--check` 位级守门**：重新生成到临时目录 → 与 `data/samples/` 逐字节比对 → 输出
  `SAMPLES_FROZEN_OK`；不一致即 exit 1。
- **假名白名单**：只允许 `data/README.md` 附录登记的公司名/项目名/人名；生成器内置断言，
  出现白名单外的实体名即报错。
- **植入自证**：每个变异注入器在改动后断言文本确实发生变化（`_require_change`），
  防 `str.replace` 锚点失配静默返回原文造出假样本。

## 四、数据目录布局

```
data/
├── README.md                 # 依据 + 数据源 + 口径（唯一数值出处）
└── samples/
    ├── G001_项目方案/
    │   ├── G001_a.docx
    │   ├── G001_b.md
    │   └── G001_c.txt
    ├── negative/
    │   └── N001_成本测算附件.md
    ├── skipped/              # 读不出正文的样本，落显式 skipped
    │   ├── S9001_scanonly.pdf
    │   └── S9003_encrypted.pdf
    ├── unsupported/          # 格式不受支持的样本
    │   └── S9101_legacy.doc
    └── truth/
        └── manifest.json     # 真值（只存输入与期望）
```

**目录与组的关系**：`manifest.json` 的 `files`/`base`/`dir` 字段记录的是
**相对 `data/samples/` 的完整路径**，调用方不需要从目录名反推组号。

样本文件按组命名，组名使用白名单假名；`truth/manifest.json` 是唯一真值入口。

**入仓规则**：`data/samples/**` 下的 `.pdf/.docx/.md/.txt/.html` 由 `.gitignore` 白名单放行；
隔离区、索引库、导出报告一律不入仓。

## 五、基准与验收

| 基准 | 输入 | 断言 | 门槛来源 |
|---|---|---|---|
| B1 抽取 | 各格式样本 | 各格式抽取非空；无文本层/加密落对应 skipped | 本文件 §2.2 |
| B2 归一化 | 全半角/页眉页脚/页码用例 | 归一后文本符合 §四.3 顺序 | `data/README.md` §四.3 |
| B3 召回 | 20 组人工构造样本 | 召回率 ≥ 90%，逐组点名 | `data/README.md` §四.7 |
| B4 聚类 | 真值分组 | 三档标签逐组一致；每簇理由非空 | `data/README.md` §四.5 |
| B5 差异摘要 | 改写/截断/换格式样本 | 摘要文案与真值差异类型一致 | `data/README.md` §四.10 |
| B6 回滚 | 隔离批次 | undo 后 sha256 逐字节一致；中断可恢复 | `data/README.md` §四.8 |
| B7 缓存 | 同目录两次扫描 | 二次耗时下降 ≥ 80% | `data/README.md` §四.9 |

**双边门**：B3/B4 不只要"没有误报"（`negative` 组不得聚簇），还要"确有检出"
（每个 `near` 组必须被召回并正确归档）。只守误报率的门在引擎整体失效时照样全绿。

**探活**：每个基准套件配一条缺陷注入（如打乱真值分组、删一个 shingle、把 skipped 洗成 ok），
断言基准必须报未达标；注入后仍绿 = 假门，当场修。

**B2/B3 落地位置**：B2 在 `tests/test_normalize.py`；B3 在 `tools/bench_recall.py`（逐组点名、
`--inject-*` 探活）与 `tests/test_recall.py`（同一引擎跑真值比对）。真值比对只有一处实现
（`src/docdedupe/recall.py`），基准工具与测试共用，避免两套口径。

## 七、数据变更流程

1. 改生成器 → 本地 `py -X utf8 tools/gen_samples.py --check` 必须红（证明生成器真变了）；
2. 重新生成 → `--check` 绿；
3. **同一次提交**内更新 `data/samples/**` + `truth/manifest.json` + （若涉及）README 的覆盖口径；
4. 跑全量基准，确认没有回退；
5. 提交信息里写明"重新生成合成样本（seed=…）"。

禁止手改 `data/samples/` 下的任何产物；禁止手改 `truth/manifest.json`。
