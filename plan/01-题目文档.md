# 10-17-doc-dedupe · 本地文档内容级去重与近重复整理器（题目文档）

> - **性质**：不参赛项目题（非模拟赛题，无赛事锚点；含金量锚点 = 受众面广度 + 确定性可评测 + 开源空白）
> - **目标产出**：仓库 `10-17-doc-dedupe`（DocDedupe / 文档查重整理器），发布 GitHub **公开仓库**，署名 yuluo554
> - **版本史**：v1 2026-10-17（初稿定稿，基准日 2026-10-17）
> - **交付形态**：**纯本地 Python CLI + 本地单页 Web 复核界面**（FastAPI + 原生 JS，无构建步骤）。单一形态，不设备选：命令行负责扫描/指纹/聚类/隔离/撤销，Web 页面负责簇复核与差异查看。**无服务器、无 GPU、无网络调用**。
> - **定位宣言**："给本机文档做'正文级查重'——跨 PDF/Word/Markdown/TXT/HTML，找出'同一份内容的多个版本'，用可读的差异对比告诉你该留哪一份，并且只隔离、不删除。现有去重工具全部止步于哈希或图像；'文档正文相似'被 czkawka 以 P3-Large effort 关闭搁置——这正是小工具的窗口。中文无空格分词、页眉页脚污染、标书/论文/合同的模板族判定，是英文工具的结构性盲区。"

## 一、介绍

**痛点**：一台电脑用了几年，同一份文档会以多个版本散落在下载目录、即时通讯接收目录、临时拷贝目录、U 盘备份里：`项目方案.docx`、`项目方案(1).docx`、`项目方案-修改版.docx`、`项目方案_final.pdf`。文件名完全不同，内容只差一段或一个署名。现有工具要么按字节哈希判定（改一个字就漏掉），要么按图片相似（对正文无效），要么只能按文件名/音乐标签比对。用户真正想知道的是三件事：**哪几份其实是同一份内容、该留哪一份、其余能不能安全收走而随时找回**。

## 二、任务要求

首期 **5 个模块**，扩展项另列。每模块写清 **输入 / 输出 / 引擎 / 确定性纪律 / 验收**。

### 模块①：扫描与格式适配层

- **输入**：一个或多个根目录路径 + 忽略规则配置。
- **输出**：本地 SQLite 索引（路径、大小、mtime、inode/dev、扩展名、正文抽取状态、正文摘要、指纹、缓存键）。
- **引擎**：目录遍历（`os.scandir`）；忽略 `.git`、`node_modules`、系统目录、隔离区 `.dedupe-quarantine/`；按扩展名/魔数识别格式；PDF **仅文本层**（pypdf 或 pdfplumber）、DOCX（python-docx，段落 + 表格）、Markdown/HTML（标准库 + 正则）、TXT（编码探测）；SQLite 缓存。
- **确定性纪律**：缓存键单点定义（见 `data/README.md` 数值口径纪律）；PDF 抽取失败或扫描件无文本层 → **显式标记 `skipped:no_text_layer`，不静默当"不重复"**；加密 PDF 标记 `skipped:encrypted`；**首期不引入 OCR**；同一输入两次扫描结果一致。
- **验收**：1000 个混合格式文档扫描不崩溃；二次扫描走缓存，耗时相对首次下降 80% 以上（口径见 data/README.md）。

### 模块②：中文友好指纹与召回

- **输入**：模块①的正文文本。
- **输出**：归一化正文 + 64-bit SimHash + MinHash/LSH 签名 + 候选相似对（含分数）。
- **引擎**：全半角归一（NFKC）、去页眉页脚/页码、去多余空白与标点噪音；**字符 3-gram shingles（非词 shingle）**；64-bit SimHash 分桶；MinHash/LSH banding 召回；先按 size / 扩展名粗筛降低候选量。
- **确定性纪律**：归一化规则与 n 值单点定义；相似度与阈值只在配置一处定义（`data/README.md` 口径）；粗筛只减少候选，不得改变召回真值口径；**中文不得使用空格分词**。
- **验收**：20 组人工构造样本（改写版 / 截断版 / 换格式版）召回率 ≥ 90%（命中判据见 data/README.md）。

### 模块③：聚类与保留建议

- **输入**：模块②的候选对与分数。
- **输出**：簇列表（并查集编号）+ 每簇"建议保留 1 份、其余可归档"的推荐 + **可解释理由字符串** + 三档分类。
- **引擎**：并查集聚类；打分维度：mtime 更新、路径更浅、文件名规范（非 `副本` / `(1)` / `~$` 前缀）、元数据更完整、目录归属；分类三档：**完全重复 / 近重复 / 模板族**（同模板合同、发票、周报会被聚簇——这是价值也是风险）。
- **确定性纪律**：打分公式单点定义；每簇必须输出人类可读理由（如"保留 `A/项目方案.docx`：修改时间最新、路径更浅、文件名无副本标记"），**不得只给裸分数**；模板族单独成档，禁止与近重复混同；**推荐只是建议，程序永不自动删除**。
- **验收**：每簇均给出可解释推荐理由字符串；三档分类与合成真值一致。

### 模块④：差异复核界面

- **输入**：模块③的簇数据。
- **输出**：本地单页 Web 复核界面：左侧簇列表（三档标签 + 推荐保留项），右侧双栏差异高亮（段落级 + 字符 n-gram 级），摘要文案形如"仅差 3 段 / 差一个署名 / 差一页"。
- **引擎**：FastAPI 本地绑定 `127.0.0.1`；原生 JS/HTML/CSS，**无前端构建链、零 CDN、零外部请求**；段落级 diff + 字符 n-gram 高亮。
- **确定性纪律**：界面只读展示；执行隔离必须由用户在界面上显式确认后调用模块⑤接口；页面不联网、不上传任何文档内容。
- **验收（功能验收）**：用户无需命令行即可完成"看簇 → 看差异 → 决定保留 → 触发隔离"的完整复核；页面应展示簇列表、三档标签、推荐理由、双栏差异高亮与差异摘要；无前端构建步骤；断网可用。

### 模块⑤：安全执行与回滚

- **输入**：用户确认的簇与保留选择。
- **输出**：`.dedupe-quarantine/<batch-id>/` 下的文件 + `manifest.json`（原路径、新路径、簇 id、分数、时间）+ CSV/JSON 报告。
- **引擎**：`shutil.move`；Windows 长路径用 `\\?\` 前缀 + 句柄重试；manifest 状态机（`pending → moved`）先写后动；一键撤销按 manifest 逆序移回；导出 CSV/JSON 报告。
- **确定性纪律**：**只隔离、不删除**；撤销前校验内容哈希，移回后原路径逐字节一致；中断后可从 manifest 恢复（未完成项按状态机续做或回退）；隔离区与索引库不入 git。
- **验收**：撤销后文件路径逐字节一致；扫描/移动中断后可从 manifest 恢复；报告字段完整可复核。

**扩展项（首期不做）**：PPTX/XLSX 正文抽取；语义向量检索；目录增量监听。

## 六、边界与非目标

- **首期不做 OCR**：扫描件 PDF 显式跳过并标记 `skipped:no_text_layer`，**不静默当"不重复"**，不承诺识别图片文字。
- **不做语义向量检索**：首期只用字符 n-gram + SimHash/MinHash，不引入 embedding 模型。
- **不自动删除**：只隔离到 `.dedupe-quarantine/`，必须可一键撤销；任何"推荐"都只是建议。
- **不处理加密 PDF**：标记 `skipped:encrypted` 后跳过。
- **不做云同步**：无账号、无上传、无遥测。
- **隐私红线**：文档内容高度敏感；**纯本地、零上传、零遥测**；隔离区与索引库（`*.db`）不入 git；真实文档不入仓、不入示例目录；示例一律合成。
- **近重复 ≠ 重复**：同模板合同/发票/周报会被聚簇，这是价值也是最大风险 → 分"完全重复 / 近重复 / 模板族"三档，模板族必须单独成档，永不自动处置。
- **品牌隔离**：本题定位为独占的**文档正文级去重整理器**；命名、文案与代码命名空间均围绕"文档正文 / 相似度 / 隔离恢复"词系，不借用其他项目词系，文档不提及任何姊妹项目。
- **首期范围限定**：仅上述 5 模块；PPTX/XLSX、语义检索、增量监听留扩展项，防 scope 失控。
- **结论纪律**：界面与报告只陈述"哪些文件相似、差在哪、建议留哪份"；相似度是机械测量值，不构成"抄袭/侵权"判断。
