### 实测记录（M2 收尾，本机 Windows / Git Bash）

| 项 | 实测 |
|---|---|
| 冻结校验 | `SAMPLES_FROZEN_OK (102 files, seed=20261017)`（未改样本，仅改抽取器后仍位级一致） |
| B3 召回（逐组点名） | **20/20 = 100%**，门槛 90%；`negative` 10 组零误报 |
| 归一化 | G005 六份（DOCX/MD/TXT/HTML/PDF + GBK 双胞胎）归一后 441 字符完全一致；G010 全半角、G011 页眉页脚+页码均归一到同一串 |
| 指纹与分数 | `pairs.score_kind = exact_jaccard`；`jaccard_estimate` 同表留档，实测 \|精确−估计\| 均值 0.020、最大 0.107 |
| 扫描（101 份） | 首次 0.99s，二次 0.03s；`94` 指纹行；`98` 条 pairs（`81` 条 ≥ 0.80） |
| 扫描（1000 份混合） | 首次 9.28s，二次 0.25s → **下降 97.3%**（门槛 ≥ 80%） |
| 二次扫描 | `1000 from cache, 0 extracted`；召回按"输入摘要 + 结果摘要"跳过，并显式说明 |
| 确定性 | 两次独立扫描 `fingerprints` / `pairs` 逐字段一致（`test_two_scans_produce_identical_fingerprints_and_pairs`） |
| 探活 | `drop-above` → 17/20 FAIL；`drop-random` → 按组点名 FAIL；`shift-groups` → 0/20 FAIL |
| 测试 | 3.8 与 3.12 各 220 项全绿 |

**关键设计取舍（写入 `data/README.md` §四.4）**：128 置换 MinHash 估计的标准误约 0.035，
而本语料最弱真值对 0.81–0.83 仅高出 0.80 阈值 0.01–0.03。若用估计值判定，边界上的是采样噪声
（实测 20 组中 4 组因此被拆散）。故 MinHash/LSH 只负责召回，判定用已存 shingle 哈希的精确 Jaccard，
估计值仍落库供审计。

**待首推验证**：CI 四矩阵与 wheel 安装面仍未实跑（仓库尚无远端），与本轮无关。
